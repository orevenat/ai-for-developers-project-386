# Дизайн‑спецификация: бэкенд бронирований

Дата: 2026-05-05

## Цели
- Реализовать серверную часть в `backend/` на Ruby/Rails (API‑only).
- Следовать контракту TypeSpec без изменений (изменения обсуждаются отдельно).
- Реализовать полные правила бронирования на стороне бэкенда.
- Использовать sqlite в dev/test и postgres в production.
- Использовать `mise` для установки и управления версией Ruby.

## Объем работ
### Входит
- Реализация всех маршрутов из `tsp/routes.tsp` для guest и admin потоков.
- Реализация моделей и сериализации по `tsp/models.tsp`.
- Генерация слотов, бронирование, обработка конфликтов и ошибок.
- Настройка окружения Rails API‑only, миграции, сиды.
- Тестирование: контроллеры и сервисы.

### Не входит
- Изменения контракта TypeSpec (только по отдельному согласованию).
- Аутентификация/авторизация админских маршрутов.

## Архитектура
- Rails API‑only приложение в `backend/`.
- Доменные сервисы для бизнес‑логики:
  - `BookingService` — создание бронирований и проверка конфликтов.
  - `SlotAvailabilityService` — генерация и расчет статуса слотов.
  - `ScheduleService` — формирование расписания для admin маршрутов.
- Контроллеры выполняют валидацию входа, вызывают сервисы, маппят ошибки в ответы.

## Модель данных
- `owners` (singleton): `name`, `avatar_url`, `workday_start`, `workday_end`.
- `event_types`: `id` (string), `name`, `description`, `duration_minutes`.
- `slots`: `id` (int), `event_type_id`, `start`, `end`, `status`.
- `bookings`: `id` (string/uuid), `event_type_id`, `slot_id`, `name`, `email`, `created_at`.

Индексы и ограничения:
- `slots(event_type_id, start)` индекс для выборок.
- `bookings(slot_id)` unique для защиты от двойного бронирования.

## Правила слотов и бронирования
- Окно бронирования фиксированное: 14 дней от текущей даты (server TZ).
- `from/to` в запросах должны лежать внутри окна; иначе `OutOfWindowError`.
- Рабочие часы берутся из `owners.workday_start/end`.
- Длительность слота = `event_type.duration_minutes`, шаг сетки = 15 минут.
- Слот `busy`, если пересекается по времени с любой записью `bookings`.
- `POST /bookings` выполняет проверки:
  - существование `event_type` и `slot`;
  - принадлежность слота к `event_type`;
  - слот в окне 14 дней;
  - слот `free` и без пересечений;
  - затем создание брони в транзакции.

## Стратегия хранения слотов
- Слоты хранятся персистентно в `slots`.
- На запрос `GET /slots` и `GET /admin/schedule` слоты генерируются в рамках окна 14 дней и upsertятся, чтобы иметь стабильные `slot_id`.

## Ошибки и транзакции
- `NotFoundError` — ресурс не найден.
- `BadRequestError` — валидационные ошибки входа.
- `ConflictError` — слот уже занят (конкурентное бронирование).
- `OutOfWindowError` — запрос вне окна бронирования.

`POST /bookings` выполняется в транзакции с опорой на DB‑constraint `bookings.slot_id` для защиты от гонок.

## Тестирование
- Используем Minitest.
- Фикстуры для базового состояния: `owners`, `event_types`, `slots`, `bookings`.
- FactoryBot используется для новых данных в тестах через `attributes_for`.
- Покрытие: все контроллеры + сервисы (модели не тестируем).

## Инфраструктура
- sqlite в dev/test, postgres в production через `DATABASE_URL`.
- Миграции и сиды для стартовых данных.
- `mise` управляет Ruby (обновление `.tool-versions`).
