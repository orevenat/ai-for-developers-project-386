# Дизайн: улучшение страницы бронирований (админ)

## Цель
Показать на админ-странице бронирований полные данные (имя, email, время начала встречи, название типа события) и дать владельцу календаря возможность отменять бронирование, оставляя его в списке со статусом "Отменен" и освобождая слот.

## Область работ
- Обновить контракт TypeSpec для списка админских бронирований и отмены.
- Обновить UI админ-страницы бронирований для отображения новых полей и действия отмены.
- Обновить backend для выдачи расширенных данных и обработки отмен.
- Добавить/обновить unit и интеграционные тесты.

## Не входит в задачи
- Изменения гостевого потока или публичного интерфейса бронирований.
- Уведомления или письма при отмене.
- Удаление бронирований вместо пометки об отмене.

## Контракт API (TypeSpec)
### Модели
- Расширить payload админских бронирований:
  - `event_type_name: string`
  - `slot_start: string` (ISO8601)
  - `status: "active" | "cancelled"`

### Эндпоинты
- `GET /admin/bookings/upcoming`
  - Возвращает `items: AdminBooking[]` с полями выше.
- `POST /admin/bookings/{id}/cancel`
  - Помечает бронирование как отмененное.
  - Освобождает связанный слот.
  - Возвращает обновленный payload бронирования.

## Дизайн backend
- Храним статус бронирования в записи (`active` по умолчанию, `cancelled` при отмене).
- Поток отмены:
  - Найти бронирование по id.
  - Обновить статус на `cancelled`.
  - Обновить статус слота на `free`.
  - Вернуть расширенный payload бронирования с названием типа события и временем начала слота.
- Список предстоящих бронирований возвращает:
  - `event_type_name` из связи `EventType`.
  - `slot_start` из времени начала слота.
  - `status` из бронирования.

## Дизайн frontend
- Обновить типы и API клиент для новых полей и эндпоинта отмены.
- Колонки таблицы:
  - Событие (event type name)
  - Гость (name)
  - Email
  - Время встречи (slot start)
  - Статус
  - Действия (кнопка отмены)
- Поведение отмены:
  - Кнопка видна/активна только для активных бронирований.
  - При успехе статус строки становится "Отменен", действие отключается/скрывается.
  - При ошибке показываем сообщение, статус строки не меняем.

## Обработка ошибок
- Ошибки загрузки списка показываются текущим StatusMessage.
- Ошибки отмены показываются через StatusMessage, бронирование остается активным.

## Тесты
- Тесты контроллера backend:
  - Список админских бронирований содержит `event_type_name`, `slot_start`, `status`.
  - Эндпоинт отмены ставит статус `cancelled` и освобождает слот.
- Тесты frontend (если есть):
  - Таблица админских бронирований отображает поля и статус.
  - Отмена обновляет статус и отключает кнопку.
- Интеграционные тесты:
  - Сквозной сценарий: бронь появляется, админ отменяет, статус меняется, слот доступен.

## Порядок реализации
1. Обновить контракт TypeSpec.
2. Обновить типы, API клиент и UI админ-страницы бронирований.
3. Обновить backend (модели/контроллеры/сервисы).
4. Запустить unit тесты, затем интеграционные.
