# Дизайн‑спецификация: фронтенд бронирований

Дата: 2026-05-05

## Цели
- Реализовать фронтенд как отдельную часть приложения в `frontend/`.
- Соблюдать контракт API на основе TypeSpec, интеграция через OpenAPI и Prism.
- Обеспечить корректную работу с отдельно запущенным бэкендом.
- Воспроизвести макеты из `docs/01-home.png`, `docs/02-book-catalog.png`, `docs/03-book-event-type.png`.

## Объем работ
### Экраны
- `/` — главная (статичная информация, без запросов к API).
- `/book` — каталог типов событий (макет `docs/02-book-catalog.png`).
- `/book/:eventTypeId` — страница типа события и слотов (макет `docs/03-book-event-type.png`).
- `/book/:eventTypeId/confirm` — подтверждение бронирования (форма имя + email).
- `/admin` — список предстоящих событий.
- `/admin/schedule` — расписание (свободные и занятые слоты).
- `/admin/settings` — настройки владельца + создание типов событий.

### Вне объема
- Аутентификация/авторизация админки (доступ по прямым ссылкам).
- Загрузка файлов (аватар указывается URL‑ом).

## Контракт и генерация клиента
- Источник: `tsp/`.
- Генерация OpenAPI по умолчанию в `tsp-output/@typespec/openapi3/openapi.json`.
- Prism‑клиент генерируется на основе OpenAPI.
- Базовый URL API задается через `VITE_API_BASE_URL` с дефолтом `http://localhost:3000`.

## Изменения контракта
- Удалить поле `time_zone` из `BookingCreate` и `Booking`.
- Фронтенд отправляет только поля, оставшиеся в контракте.

## Маршруты и данные
### Guest поток
- `GET /event-types` → каталог типов событий.
- `GET /event-types/{event_type_id}` → страница типа события.
- `GET /slots?event_type_id=...&from&to` → список слотов (по умолчанию окно 14 дней).
- `POST /bookings` → создание бронирования (name, email, event_type_id, slot_id).

### Admin поток
- `GET /admin/bookings/upcoming` → список предстоящих бронирований.
- `GET /admin/schedule?from&to` → расписание с free/busy слотами.
- `GET /admin/settings` → профиль владельца + параметры рабочего дня.
- `POST /admin/event-types` → создание типа события.
- `GET /admin/event-types` → список типов событий (для управления).

## UI/UX и состояния
- Mantine для layout и компонентов.
- Состояния: loading/empty/error на каждом экране.
- Отображение ошибок по `ErrorResponse.message`.
- После успешного бронирования — экран подтверждения/успеха (в рамках маршрута `/book/:eventTypeId/confirm`).

## Архитектура фронтенда
- `frontend/` как отдельный пакет.
- React Router для маршрутизации.
- Слой `api/` на базе Prism клиента с единым перехватом ошибок.
- Конфигурация через `.env` (Vite).

## Нефункциональные требования
- Работает с отдельно запущенным бэкендом.
- Код соблюдает TypeScript типобезопасность.
- Никаких прямых обращений к данным вне API.
