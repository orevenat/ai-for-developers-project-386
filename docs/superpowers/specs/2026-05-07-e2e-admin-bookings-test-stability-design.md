## Цель
Сделать e2e тест бронирования устойчивым к уже существующим отмененным записям, ограничив проверки записью, созданной в тесте.

## Проблема
Сейчас тест проверяет, что в таблице админки нет ни одной ячейки со статусом "Отменен". Это падает, если в данных уже есть отмененные записи.

## Подход
- Генерировать уникальный маркер (например, на основе времени) для имени и email гостя, создаваемых в тесте.
- В таблице админки находить строку, содержащую этот маркер.
- Проверять статус только в этой строке, затем отменять запись в ней же и ожидать смену статуса на "Отменен" только для этой строки.

## Поведение теста
- Создание брони не меняется, кроме использования уникального имени/email.
- Тест ждет появления строки с маркером в таблице админки перед проверкой статуса.
- Проверка статуса ограничена строкой с маркером.
- Отмена выполняется через кнопку "Отменить" внутри этой строки.

## Селекторы и область поиска
- Использовать локаторы строки Playwright (например, `getByRole('row', { name: /<marker>/ })`) для ограничения области.
- Внутри строки использовать `getByRole('cell', { name: 'Отменен' })` для проверки статуса и `getByRole('button', { name: 'Отменить' })` для действия.

## Риски и снижение
- Если маркер попадет в несколько строк, использовать более уникальный маркер (timestamp + случайный суффикс) и искать по имени и email.
- Если строка не появляется, сохранить существующие ожидания загрузки и добавить явное ожидание строки.

## Проверка
- Запустить `npm run test:e2e` и убедиться, что тест "guest booking flow" проходит при наличии отмененных записей в данных.
