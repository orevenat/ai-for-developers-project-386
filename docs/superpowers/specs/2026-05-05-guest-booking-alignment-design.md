# Дизайн‑спецификация: выравнивание гостевого потока бронирований

Дата: 2026-05-05

## Цели
- Максимально приблизить гостевой поток к примеру nurgeldy-calendar-booking, оставаясь в рамках Mantine.
- Улучшить конверсию бронирований за счет понятного пошагового сценария.
- Сохранить текущую архитектуру и API‑контракт.

## Объем работ
### Экраны
- `/` — главная: hero + CTA + блок “Возможности”.
- `/book` — каталог типов встреч.
- `/book/:eventTypeId` — выбор даты и времени.
- `/book/:eventTypeId/confirm` — подтверждение бронирования и успех‑состояние.

### Вне объема
- Админка (`/admin` и вкладки).
- Изменения API‑контракта.

## Подход
- Подход 2: выделить UI‑примитивы и на них перестроить гостевой поток.
- Минимально менять текущие данные и запросы, фокус на структуре, визуале и состояниях.

## UX‑структура
### `/`
- Hero: заголовок, подзаголовок, иллюстрация, CTA “Записаться”.
- Блок “Возможности”: 3–4 карточки с иконкой, заголовком, кратким описанием.

### `/book`
- Блок владельца (аватар/имя/роль).
- Заголовок “Выберите тип встречи” + пояснение.
- Карточки типов встреч с CTA “Выбрать дату”.

### `/book/:eventTypeId`
- Левый инфоблок: организатор, тип встречи, длительность, выбранные дата/время.
- Правый блок: календарь + список слотов.
- Кнопки “Назад/Продолжить” внизу.

### `/book/:eventTypeId/confirm`
- Резюме встречи: тип, дата, время, длительность.
- Форма: имя и email.
- Успех‑состояние на этом же маршруте.

## Компоненты
- `HeroSection`
- `FeatureCard`
- `EventTypeCard`
- `BookingSummaryPanel`
- `SlotButton`
- `EmptyState`

## Визуальные токены
- Единые цвета (основной, акцент, нейтраль), радиусы, тени, интервалы, размеры иконок.
- Состояния hover/active/disabled для карточек и слотов.

## Данные и состояния
### `/book`
- Loading/empty/error для списка типов.

### `/book/:eventTypeId`
- Loading/empty/error для типа встречи.
- Календарь: прошедшие/недоступные дни disabled.
- Слоты: свободные активны, занятые disabled с меткой “Занято”.
- “Продолжить” активна только после выбора слота.

### `/book/:eventTypeId/confirm`
- Валидация имени и email.
- Ошибки API через `ErrorResponse.message`.
- Успех‑состояние без перехода на отдельный маршрут.

## Ошибки и UX‑поведение
- Для ошибок API использовать `EmptyState`/`StatusMessage` с CTA “Повторить”.
- Явный сценарий “Выбор даты → Выбор времени → Подтверждение”.
- Подсказка до выбора даты, пока слоты недоступны.

## Критерии готовности
- Внешний вид ключевых экранов близок к примеру.
- Полный путь бронирования без тупиков.
- Disabled‑слоты визуально отличимы и недоступны для выбора.
